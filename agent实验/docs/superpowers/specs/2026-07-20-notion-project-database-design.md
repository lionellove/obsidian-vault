# Notion Project Database 设计方案

## 1. 背景与目标

### 1.1 背景
用户当前在 Obsidian 中使用 Kanban + Dashboard 管理任务，但希望将**项目/任务的进度管理**迁移到 Notion，而**项目的具体内容、笔记、资料**继续保留在 Obsidian 中。两者通过链接实现联动。

### 1.2 目标
- 在 Notion 中追踪项目的**状态流**和**里程碑/阶段**进度。
- 在 Obsidian 中管理项目的具体内容和深度笔记。
- 通过 Notion ↔ Obsidian 链接实现最小可行的双向可达。
- 模板具备通用性，同时适用于**学术研究项目**和**个人管理类项目**。

### 1.3 成功标准
- 能一眼看清所有项目的当前阶段和整体状态。
- 能追踪项目下每个任务的执行状态。
- 项目完成百分比由任务状态自动计算。
- 点击链接即可从 Notion 跳转到 Obsidian 对应页面。
- 结构不过度复杂，个人用户可长期维护。

---

## 2. 总体架构

采用 **Projects + Tasks 双 Database 结构**：

- **Projects Database**：管理项目目标、当前阶段、整体状态、时间范围、Obsidian 索引链接。
- **Tasks Database**：管理具体任务，与项目关联，承载状态流和实际执行细节。
- **Relation + Rollup**：Projects 自动汇总其下任务的完成百分比。
- **Views**：提供表格、看板、日历等多种视图，适配不同使用场景。
- **Obsidian 联动**：通过 Obsidian URL 实现手动跳转，预留未来双向同步扩展空间。

## 3. Projects Database 设计

### 3.1 字段定义

| 字段名 | 类型 | 选项/说明 | 用途 |
|--------|------|-----------|------|
| 项目名称 | Title | 项目标题 | 核心标识 |
| 项目类型 | Select | 学术研究 / 个人管理 / 内容创作 / 其他 | 分类过滤 |
| 当前阶段 | Select | 选题立项 / 资料收集 / 方案设计 / 执行实施 / 分析总结 / 输出交付 / 已完成 | 里程碑语义 |
| 项目状态 | Select | 未开始 / 进行中 / 阻塞 / 已完成 / 已搁置 | 健康度判断 |
| 优先级 | Select | P0 / P1 / P2 / P3 | 排序 |
| 开始日期 | Date | - | 时间规划 |
| 截止日期 | Date | - | 时间规划 |
| 项目目标 | Text | 一句话描述项目目标 | 快速理解项目 |
| Obsidian 索引 | URL | 链接到 Obsidian 中该项目的索引页 | 联动入口 |
| 关联任务 | Relation | 指向 Tasks database | 绑定项目下所有任务 |
| 任务总数 | Rollup | 关联任务的 Count All | 自动统计 |
| 已完成任务 | Rollup | 关联任务中状态=已完成的 Count | 自动统计 |
| 完成百分比 | Formula | 已完成任务 / 任务总数 × 100 | 自动计算 |
| 备注 | Text | 额外说明 | 灵活补充 |

### 3.2 字段说明

- **当前阶段** 承担里程碑语义，项目在各阶段间推进。
- **项目状态** 反映整体健康，遇到阻塞任务时手动标为"阻塞"。
- **Rollup 字段** 自动从 Tasks 汇总进度，无需手动更新。

## 4. Tasks Database 设计

### 4.1 字段定义

| 字段名 | 类型 | 选项/说明 | 用途 |
|--------|------|-----------|------|
| 任务名称 | Title | 任务标题 | 核心标识 |
| 所属项目 | Relation | 指向 Projects database | 与项目关联 |
| 项目阶段 | Rollup | 取所属项目的"当前阶段" | 自动继承项目阶段 |
| 任务状态 | Select | 未开始 / 进行中 / 阻塞 / 待验收 / 已完成 / 已取消 | 状态流 |
| 优先级 | Select | P0 / P1 / P2 / P3 | 排序 |
| 任务类型 | Select | 研究 / 写作 / 实验 / 开发 / 会议 / 杂项 | 分类 |
| 计划日期 | Date | - | 安排执行 |
| 截止日期 | Date | - | 截止时间 |
| 实际完成日 | Date | - | 记录真实完成时间 |
| 预计工时 | Number | 小时 | 工作量估算 |
| 实际工时 | Number | 小时 | 实际投入 |
| Obsidian 笔记 | URL | 链接到 Obsidian 中该任务的笔记 | 联动入口 |
| 前置任务 | Relation | 指向 Tasks database（自引用） | 表达依赖关系 |
| 阻塞原因 | Text | 当状态=阻塞时填写 | 记录为什么卡住 |
| 描述 | Text | 任务详情 | 补充信息 |

### 4.2 字段说明

- **项目阶段** 用 Rollup 从 Projects 继承，方便按阶段过滤任务。
- **前置任务** 自引用支持任务依赖链。
- **待验收** 状态适合需要检查/审阅的任务，例如论文初稿完成后等待修改。

## 5. Relation 与 Rollup 设计

### 5.1 Projects → Tasks

| Projects 字段 | 类型 | 来源 |
|---------------|------|------|
| 关联任务 | Relation | Tasks.所属项目 |
| 任务总数 | Rollup | Count All of 关联任务 |
| 已完成任务 | Rollup | Count where 任务状态 = 已完成 |
| 完成百分比 | Formula | `prop("已完成任务") / prop("任务总数") * 100` |

### 5.2 Tasks → Projects

| Tasks 字段 | 类型 | 来源 |
|------------|------|------|
| 所属项目 | Relation | Projects |
| 项目阶段 | Rollup | Projects.当前阶段 |

### 5.3 Tasks 自引用

| Tasks 字段 | 类型 | 来源 |
|------------|------|------|
| 前置任务 | Relation | Tasks（同一个 database） |

## 6. Views 设计

### 6.1 Projects Database Views

| 视图名 | 类型 | 分组/过滤 | 用途 |
|--------|------|-----------|------|
| 项目总览 | Table | 按优先级排序 | 所有项目一览无余 |

| 本月聚焦 | Table | 过滤开始日期或截止日期在本月 | 近期重点工作 |
| 画廊视图 | Gallery | 卡片展示项目目标和进度 | 视觉化概览 |

### 6.2 Tasks Database Views

| 视图名 | 类型 | 分组/过滤 | 用途 |
|--------|------|-----------|------|
| 任务清单 | Table | 按截止日期排序 | 所有任务管理 |
| 状态流看板 | Board | 按"任务状态"分组 | 看板拖拽推进任务 |
| 今日待办 | Table | 过滤计划日期=今天 | 每日执行清单 |

| 阻塞项 | Table | 过滤状态=阻塞 | 集中处理卡点 |

## 7. Notion ↔ Obsidian 联动机制

### 7.1 方案选择

- **当前方案：手动链接（A 方案）**
  - Notion 项目/任务卡片中放置 Obsidian 笔记链接。
  - 点击链接直接跳转到 Obsidian 对应页面。
  - 维护成本低，立即可用。

- **未来可扩展：双向同步（B 方案）**
  - 若未来有稳定工具，可升级至双向同步。
  - 当前数据库结构已为该扩展预留接口。

### 7.2 Obsidian 端目录结构

```
Vault/
├── Projects/
│   ├── 项目名称A/
│   │   ├── README.md          # 项目索引页
│   │   ├── 资料/
│   │   ├── 笔记/
│   │   └── 任务/
│   └── 项目名称B/
│       └── README.md
```

### 7.3 项目索引页模板

```markdown
# 项目名称

- Notion 项目页：[链接]
- 目标：
- 当前阶段：
- 关键截止日期：

## 关键笔记
- [[相关资料]]

## 任务日志
- [ ] 任务1
```

### 7.4 Notion 端链接格式

- **Projects.Obsidian 索引**：`obsidian://open?vault=你的Vault名&file=Projects%2F项目名称%2FREADME`
- **Tasks.Obsidian 笔记**：对应任务笔记的 Obsidian URL

### 7.5 命名约定

- Notion 项目名 = Obsidian 文件夹名
- Notion 任务名 = Obsidian 任务笔记标题

统一的命名约定即使不点击链接，也能帮助在两边快速定位。

### 7.6 双向同步扩展选项

| 方案 | 工具 | 说明 |
|------|------|------|
| 插件同步 | Obsidian Notion Sync 社区插件 | 配置 Notion Integration Token 后单向或双向同步 |
| 自动化平台 | n8n / Make | 通过 Notion API 和文件系统监控实现自定义同步 |
| Markdown 导出 | Notion 导出功能 | 定期导出为 Markdown，Obsidian 直接读取 |

**建议：** 当前阶段使用手动链接；流程稳定后，如需同步，优先尝试 **Notion → Obsidian 单向同步**，降低冲突风险。

## 8. 可选 Notion 自动化

| 触发条件 | 动作 | 用途 |
|----------|------|------|
| 任务状态改为"已完成" | 自动填写"实际完成日"=今天 | 减少手动记录 |
| 项目下所有任务都完成 | 项目状态自动改为"已完成" | 项目自动收尾 |
| 任务状态改为"阻塞" | 所属项目状态改为"阻塞" | 自动上报风险 |
| 截止日期临近 3 天 | 给任务加标签"即将到期" | 提醒聚焦 |

**注意：** Notion 自动化功能在部分付费计划中受限，免费版可能无法使用。可先手动运行，确认价值后再考虑升级。

## 9. 使用流程示例

### 9.1 创建新项目

1. 在 Projects Database 中新建一行，填写项目名称、类型、目标、起止日期。
2. 在 Obsidian 中创建 `Projects/项目名称/README.md` 索引页。
3. 将 Obsidian URL 填入 Projects 的"Obsidian 索引"字段。

### 9.2 拆解任务

1. 在 Tasks Database 中新建任务，关联到对应项目。
2. 填写任务状态、优先级、计划日期、截止日期。
3. 如任务有内容笔记，在 Obsidian 中创建任务笔记并填入 URL。

### 9.3 推进任务

1. 在"状态流看板"视图中拖拽任务状态。
2. 任务完成后，Projects 的"完成百分比"自动更新。
3. 根据完成情况调整 Projects 的"当前阶段"。

### 9.4 周回顾

1. 打开"本周计划"视图，检查本周任务完成情况。
2. 打开"阻塞项"视图，处理卡住的依赖任务。
3. 打开"阶段看板"视图，确认各项目里程碑推进节奏。

## 10. 范围边界

### 10.1 包含

- Notion 中 Projects 和 Tasks 两个 Database 的字段、关系、视图设计。
- Notion 与 Obsidian 之间的手动链接联动方案。
- 可选自动化的规则建议。

### 10.2 不包含

- 具体 Notion Integration Token 的申请与配置步骤。
- n8n 或 Notion Sync 插件的详细部署教程。
- 与除 Obsidian 外其他工具的集成。
- 团队协作权限管理（按个人使用设计）。

## 11. 后续可扩展方向

- 增加 **Milestones Database**，将阶段从 Select 升级为独立 Database，适合大型研究课题。
- 增加 **Time Tracking Database**，记录每日/每周在各个任务上的时间投入。
- 增加 **Resources Database**，统一管理文献、资料、链接，并与项目和任务关联。
- 接入 n8n 实现 Notion 与 Obsidian 的自动双向同步。
